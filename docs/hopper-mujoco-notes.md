# 一本脚ホッパー MuJoCo 移行ノート — 何が起きて、どう直したか

作成: 2026-09-08　対象: `hopper/`（`model.py` / `controller.py` / `run.py`）、`notebooks/02_hopper_mujoco.ipynb`

2D シミュレーター（`tools/webapp/hopper-2d.html`、`hopper-roll-2d.html`）で成立した機体と Raibert 制御を MuJoCo に移すまでに 7 回の修正を要した。
どれも「2D では暗黙に仮定していたことが 3D の物理エンジンでは成り立たない」種類の問題で、今後の四脚 MJCF 作成や実機でも同じ落とし穴を踏む。
時系列で、症状 → 診断 → 原因 → 修正 → 教訓 の順に残す。

---

## 0. 進め方の型（先に結論）

1. **まず「その場ホップ」を 2D の数字と突き合わせる**。前進や横移動は、その場が合ってから。
2. 転倒したら `trace()`（10 ms ごとの内部状態表）を見る。`summarize` の数字だけでは原因は分からない。
3. 見る順番は固定: 拘束が効いているか（`nefc`、スライド量）→ 接地とバネ圧縮（`cont`、`Fn`、`delta`）→ 位相遷移（`phase`）→ 指令と実トルク（`tc`、`f`）→ 姿勢（`th`、`om`、`Mcmd`）。
4. 符号の疑いは**運動学の一致チェック**（`check_kinematics()`）と**初期外乱の応答**（`trace(th0=0.1)`）で潰す。推測で符号を変えない。
5. サーボ負荷は 5 ms 平均の持続ピークで読む。瞬時値は指令段差で必ず 100 % に触れる。
6. 直したらノートブックのセル 1b（`git pull` ＋ `reload`）で取り込む。ノートブックのセル自体を変えたときだけ GitHub から開き直す。

## 1. 修正の履歴

### 1 回目: 1 s で転倒、バネが縮まない

- 症状: `apex −0.3 cm`、`delta 0.0 mm`、接地力 17 N（本来 65 N）、接地 120 ms（本来 165 ms）、脚長サーボ 7 %。
- 診断: `trace()` で着地後も `delta` が 0 のまま。
- 原因: 直列バネのスライドを、先端に `connect` で固定した**キャリア自身**に置いていた。拘束がスライドを止め、バネが動けなかった。
- 修正: バネのスライドを**足側**（キャリアの子）に移動。キャリアは先端に追従するだけ。
- 教訓: `connect` で位置を固定した物体に自由度を持たせても動かない。「拘束される物体」と「動く自由度」は分ける。

### 2 回目: 0.27 s で転倒、脚が支えない

- 症状: 0 ホップ。`trace()` でキャリアのスライド `cz` が 0.26 s で **133 mm**、クランクは 18° しか動かない。`nefc 10`、`eq_active True` で拘束自体は有効。
- 原因: MuJoCo の拘束は既定（`solref 0.02 1`）だと**関係する物体の有効質量に比例した柔らかさ**になる。キャリア 5 g・先端 2 g では 23 N の荷重で十数 cm ずれる。
- 修正: `connect` に `solref="-30000 -300"`（負値＝剛性・減衰の直接指定）。先端 2 → 5 g、キャリア 5 → 10 g。
- 教訓: **軽い部品を拘束でつなぐときは solref を直接指定する**。`nefc` や `eq_active` は「拘束が存在する」ことしか示さず、「効いている」ことは示さない。

### 3 回目: 跳べたがピッチが毎ホップ 1° → 6° → 21° と増えて転倒

- 症状: その場で 3 ホップ、頂点 5.7〜7.8 cm、`vx −0.26`、ピッチ 21°。
- 診断: `check_kinematics()` で解析 FK と MuJoCo の先端位置は一致（diff 0）。`trace(th0=0.1)` で、**圧縮中は `Mcmd` +4.6 でピッチ 6.4° → 3.0° に戻る**（符号は正しい）が、**蹴り出し中に 3.0° → 9.4° に戻る**。
- 原因: 3D では直列バネを脚面の鉛直方向（胴体基準）に置いていた。足が前後にずれると接地力の作用線が股（重心）を外れ、「ずれ量 × 接地力」の機首上げモーメントが出る。2D はバネを股→先端の線上に置いていたので出なかった。
- 修正: 股で自由に回る**脚バー**（ヒンジ）を追加し、その軸上にキャリアのスライドと足のバネを置いた。接地力の作用線が常に股を通る。
- 教訓: 2D で「当然そうなっている」幾何は、3D で組み直すときに崩れる。**力の作用線がどこを通るか**を先に決めてから部品を配置する。

### 4 回目: 圧縮中は戻るが蹴り出しで再び機首上げ

- 症状: `trace(th0=0.1)` で圧縮中は 6.6° → −0.3° まで戻るのに、蹴り出しで `om` が −0.56 → +0.85 rad/s。
- 診断: 蹴り出し中、クランク①が **4.4 rad/s（無負荷回転数の 1.4 倍）**、②はほぼ静止。`f1 2.29 / f2 −6.63` と大きく非対称。
- 原因: 胴体のわずかな後退で脚が掃引し、蹴り出し（両クランク逆方向）に掃引（同方向）が重なって片方だけ速度飽和する。蹴り出し力が非対称になり、同方向成分＝足先の接線力＝ピッチモーメント（−4 N·m）が寄生する。無負荷回転数を超えて逆駆動されたサーボは物理的に制動トルクしか出せないので、配分だけでは消せない。
- 修正: `allocate()` で**姿勢優先のトルク配分**（同方向成分を先に確保し、逆方向成分は各サーボのトルク─速度範囲に収まる分だけ）＋ 蹴り出しトルク上限 `thrust_frac`（0.6 → 後に 0.75）で速度飽和の余裕を残す。
- 教訓: 2D で「前進 0.2 m/s 以上で速度予算を使い切る」と結論した現象は、3D ではその場ホップの微小な動きでも顔を出す。**トルクの向きごとに、サーボが今出せる範囲**を意識する。

### 5 回目: ピッチは収束、頂点が 5.8 → 2.9 cm と減衰して転倒

- 症状: 8 ホップ、ピッチ ±1°。蹴り出し量が 21 → 27 mm と増えても頂点が落ちる。接地 200〜235 ms、接地力 45 N（2D は 165 ms、65 N）。
- 原因: MuJoCo 既定の接触（`solref 0.02 1`）は時定数 20 ms で質量比例。50 g の足では柔らかく、着地のたびにエネルギーを失う。
- 修正: 足と床の `solref` を 2D と同じ剛性 20000 N/m・臨界減衰 63 N·s/m で直接指定。
- 教訓: **接触も拘束と同じで、軽い物体では既定が柔らかすぎる**。接地時間と接地力ピークを 2D と比べれば気づける。

### 6 回目: 高さは回復、前進速度が周期 2 で発散

- 症状: `vx` が 0.07 → −0.15 → 0.14 → −0.38 と符号を変えながら増える。2D の §8.6 と同じ。
- 診断: `sweep_gains()` で `cn` × `Kv` を掃引。**生き残るのは `cn 0.3〜0.4 / Kv 0.01〜0.02` だけ**（2D の 0.5 / 0.03 は転倒）。その場でも −0.1〜−0.15 m/s の定常後退。
- 原因: 3D では接地写像（入口速度・足先オフセット → 出口速度）が 2D と違い、切片（定常の押し）も持つ。
- 修正: 既定を `cn 0.35 / Kv 0.02` に変更。足先配置に**ホップ単位の積分補正** `ki`（0.004 m/(m/s)/hop、±30 mm）を追加して定常偏差を消す。
- 教訓: 速度ループの係数は機体・環境ごとに測り直す。**定常偏差は `Kv` を上げて消そうとしない**（転倒する）。積分で消す。

### 7 回目: 前進 0.2 m/s で高さ制御が振動して転倒

- 症状: 8 s 追従後、蹴り出しが 17 → 1 → 0 → 8 → 36 → 50 mm と暴れて頂点が崩れる。
- 原因: 頂点 8.2 cm の行き過ぎで蹴り出しを 0 にしたホップで着地エネルギーを失い、立て直しきれない。前進中は掃引でサーボが 98 % なので、回復に必要な蹴り出しを出せない。
- 修正: 高さ調整ゲイン `kh` 0.5 → 0.3、蹴り出し量の下限 3 mm。前進の巡航は 0.15 m/s と定める。
- 結果: 前進 0.15 m/s で 53 ホップ成立（0.17 m/s、脚長サーボ 55 / 78 %）。0.2 m/s は速度上限で転倒（2D の予測どおり）。

### 8 回目（3D 固有）: 横移動でヨーが毎ホップ 19° 回る

- 症状: 横 0.2 m/s は成立するが `yaw` が 69 → 88 → 107 → … と回り続ける。前進ではゼロ。
- 原因: 点接地は鉛直軸まわりの摩擦を持たない。飛行中に足を横へ振る反作用で胴体がヨー回転し、接地でも止まらない。
- 修正: 足に捩り摩擦（`foot_pad`、`condim 4`）を追加。`yaw_test()` で比較し、**20 mm 相当（ゴムパッド半径 25 mm）で 18.7 → 3.8°/hop**、横速度・ロールサーボ負荷は悪化なし。既定に採用。
- 教訓: ヨーは 2D では原理的に見えない。3D 化の目的の一つがこれで、**実機の足はパッド付き**にする。前進だけならドリフトは出ない。

## 3. コツ（一般化できるもの）

**MJCF を書くとき**
- 閉ループの `connect` は **site 同士**で結ぶ。`anchor` 指定だと相手側の点が既定姿勢 qpos0 で決まり、初期姿勢と食い違う。
- 数 g の部品を拘束・接触に使うときは `solref` を負値で直接指定する。既定は質量比例で柔らかい。
- 力の作用線（接地力が股を通るか）を先に決めて部品を配置する。バネの向きは「見た目の鉛直」ではなく「股→足」。
- サーボのトルク─速度直線は `general` アクチュエータ `gaintype="fixed" biastype="affine" biasprm="0 0 -k"` で表せる（`biastype` を忘れると `biasprm` は無視される）。ホストは `ctrl = τ_des + k·q̇` を送る。
- 反射慣性は `armature`。ヒンジ軸の向きで角度の符号が決まるので、解析運動学と `check_kinematics()` で一致を確認する。
- 接触センサ `touch` の site は接触点を含む大きさにする（足の球より大きく）。

**制御を移植するとき**
- 2D の係数はそのまま使わない。`sweep_gains()` で安定域を測り直す。安定域は 3D の方が狭い。
- 定常偏差は積分で消す。`Kv` を上げると転倒する。
- 高さ制御は行き過ぎより「蹴り出し 0」が危険。下限を設ける。
- 姿勢トルクは蹴り出しに埋もれる。トルク配分で姿勢を優先し、蹴り出しに上限を付ける。

**診断のとき**
- `summarize` の 3 行で全体、`hop_table` でホップごとの傾向、`trace()` で 10 ms ごとの内部状態、の 3 段階で見る。
- 「符号が逆」を疑ったら、初期外乱を与えて指令と応答の向きを見る。圧縮中と蹴り出し中で分けて読む。
- 2D と比べるべき数字は 4 つ: 頂点、接地時間、接地力ピーク、サーボの持続ピーク。どれかが大きく違えばモデルの写し間違い。
- 同じ数値が 2 回続けて出たら、修正が取り込まれていない（`git pull` と `reload` を確認）。

- コード修正はセル 1b（`git fetch` → `reset --hard` → `reload`）。関節名の末尾で新旧を判別できる。
- ノートブックのセルを変えたら GitHub から開き直す。
